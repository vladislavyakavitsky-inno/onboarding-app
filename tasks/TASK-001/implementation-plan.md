# TASK-001 Implementation Plan: Training Sessions Workspace

Inputs: `tasks/TASK-001/requirements.md` (AC-1..AC-20, D-1..D-5, OQ-1), `tasks/TASK-001/workflow-log.md`, and inspection of the repository root.
Application Root: repository root, the only frontend candidate (React 19, TypeScript 6, Vite 8, oxlint).
Scope guard: nothing outside the requirements. No routing, search, pagination, edit/delete, persistence or backend.

## 1. Current vs. Intended Behavior

**Current:** `src/App.tsx` is the Vite starter (counter and marketing links). `src/main.tsx` renders `<App />` directly. There is no test runner, HTTP mock, HTTP client or `test` script. Existing scripts: `dev`, `build` (`tsc -b && vite build`), `lint` (`oxlint`), `preview`.

**Intended:** `App` renders a single Training Sessions workspace:
- It loads sessions from `GET /api/sessions`, served by a mock, and shows a loading state, then the list, or a recoverable error.
- One status filter (`All` plus four statuses) controls the list.
- A "New session" action opens a form (title + date/time) that validates, submits `POST /api/sessions`, closes on success and shows the new session.

## 2. Decisions Made in This Plan

These were left open to planning by the requirements (Gaps and Owners). All are small, and none is a specialist-level architecture change.

| ID | Decision | Rationale |
| --- | --- | --- |
| P-1 | The request boundary is a small typed module (`api.ts`) using `fetch`, with a thin `ApiError`. The UI only calls its functions. | AC-17. No HTTP-client library is needed. |
| P-2 | The mock is MSW: `setupWorker` in the browser (dev only), `setupServer` in tests. Handlers are shared. | AC-18. Conventional and reuses the same handlers everywhere. |
| P-3 | Test stack is Vitest (native to Vite), React Testing Library, `@testing-library/user-event`, `@testing-library/jest-dom`, jsdom, plus `msw`. | Matches the Vite toolchain. |
| P-4 | State lives in one feature hook (`useSessions`) with local `useState`, without a global store. Created sessions are added to local state and not re-fetched. | AC-14 and minimal scope. |
| P-5 | Status values in code are `planned`, `in-progress`, `completed`, `cancelled`, with labels `Planned`, `In progress`, `Completed`, `Cancelled` (D-1). The server (mock) assigns `planned` on create. | AC-15. |
| P-6 | The list is displayed sorted by `startsAt` ascending, so the created session lands in a predictable position. | Not specified by requirements. This is a display choice only, with no user-facing control. |
| P-7 | The date/time control is a native `<input type="datetime-local">`. The value is parsed as local time. "Future" means `startsAt >= now + 60 s` at submit time (D-4, OQ-1 default). | A3, AC-11. |
| P-8 | Wire format: `startsAt` is an ISO 8601 UTC string (`toISOString()`). It is displayed with `Intl.DateTimeFormat` in the local locale. | Unambiguous transport, local display (A3). |

## 3. Provisional API Shape (minimal, not a full contract)

- `GET /api/sessions` → `200` with `Session[]`.
- `POST /api/sessions` with body `{ "title": string, "startsAt": string }` → `201` with the created `Session`. The server sets `id` and `status: "planned"`.
- `Session = { id: string; title: string; status: SessionStatus; startsAt: string }`.
- Any non-2xx response or network failure is surfaced by the boundary as a single `ApiError`. The UI shows generic user-facing messages, not server text. Only `ApiError` semantics matter; there is no error-body contract.
- The trimmed title is sent, and the mock does not re-validate beyond basic presence.

## 4. Files

Paths under `src/`, unless noted. "New" or "Modify" is relative to the current repo.

### Configuration and dependencies (Step A)
- **Modify `package.json`:** add `test` script (`vitest run`). Add dev dependencies: `vitest`, `jsdom`, `@testing-library/react`, `@testing-library/user-event`, `@testing-library/jest-dom`, `msw`. Add MSW's `workerDirectory` entry (`public`) if `msw init --save` produces it.
- **Modify `vite.config.ts`:** add the Vitest `test` block (jsdom environment, `setupFiles`, CSS handling not needed, no globals). Use the `defineConfig` overload that supports `test`.
- **Modify `tsconfig.app.json`:** only if needed so `tsc -b` type-checks test files and jest-dom matcher types. The setup file imports `@testing-library/jest-dom/vitest` explicitly. Do not enable strict mode.
- **New `public/mockServiceWorker.js`:** generated by MSW's own init command. Do not hand-edit.
- Dependency versions: install the latest releases compatible with Vite 8 and React 19. Verify the resolved versions and peer-dependency warnings, and record them in the coder report. If Vitest or MSW cannot be made compatible with the installed Vite/TypeScript, STOP and report the conflict.

### Domain and boundary (Step B)
- **New `features/sessions/types.ts`:** `SessionStatus` (union of four values), `Session`, `NewSessionInput`, plus a status list and label map used by the filter, list and validation.
- **New `features/sessions/api.ts`:** `fetchSessions(signal?)` and `createSession(input)`. Both go through `fetch` against relative `/api/sessions`. Non-2xx and network failures raise `ApiError`. No hard-coded data.

### Mock (Step C, depends on B types)
- **New `mocks/seed.ts`:** 5–8 sessions covering all four statuses (A6, D-5). Dates should be fixed literals, with a mix of past and future.
- **New `mocks/handlers.ts`:** `createHandlers({ latencyMs })` returns the two handlers backed by in-memory state cloned from the seed. Provide a reset function for tests. POST assigns `id` and `status: "planned"`. Latency is configurable so tests use 0.
- **New `mocks/browser.ts`:** `setupWorker(...createHandlers({ latencyMs: ~500 }))`. The delay makes the loading state observable in the manual check.
- **New `mocks/server.ts`:** `setupServer(...)` for tests, with no latency.
- **Modify `main.tsx`:** in development only (`import.meta.env.DEV`), dynamically import and start the worker (`onUnhandledRequest: "bypass"`) before rendering, so the mock code is not part of a production build. `StrictMode` stays.

### Validation (Step D, independent of C)
- **New `features/sessions/validation.ts`:** pure functions.
  - `validateTitle(raw)`: trims and requires 3–80 characters, returning a specific message (for example "Title must be at least 3 characters").
  - `validateStartsAt(rawLocalValue, now)`: requires a value, a parseable date, and `>= now + 60 s`, with a specific message for missing versus not-in-the-future.
  - Both return a result object with the normalized value or a message. No React inside.

### State (Step E, depends on B)
- **New `features/sessions/useSessions.ts`:** owns `sessions`, `status` (`loading | error | ready`), the `filter` (`All` or a status), `load()` and `retry`, and `create(input)`.
  - `load` runs on mount and aborts or ignores stale results on cleanup, so `StrictMode` double-invocation is safe (AC-3).
  - `retry` re-issues the list request and returns to the loading state (AC-4).
  - `create` appends the returned session to local state and leaves the filter untouched (AC-7, AC-14). It rejects with the error so the form can show it.
  - Exposes `visibleSessions`, filtered by the current filter and sorted per P-6.

### UI (Step F, depends on D and E)
- **New `features/sessions/SessionsWorkspace.tsx`:** composes the page: heading, filter, "New session" button, the list region and the form. Owns whether the form is open.
- **New `features/sessions/SessionFilter.tsx`:** `All` plus four options, exactly one selected, default `All` (AC-5). Use a native labeled control (a radio group or a `<select>` with a visible label). Coder picks one; it must be keyboard operable.
- **New `features/sessions/SessionList.tsx`:** renders title, status label and formatted start date/time per item (AC-2). It renders a simple empty message when nothing matches (A4).
- **New `features/sessions/CreateSessionForm.tsx`:**
  - Labeled title and date/time fields.
  - Validates on submit using `validation.ts`, showing each message next to its field (AC-10..12), with `aria-invalid` and `aria-describedby` wiring.
  - Sets a submitting flag: the submit button is disabled and a guard in the handler ignores re-entry, covering double-click and Enter (AC-13).
  - On success it closes and resets (AC-14, D-3).
  - On failure it keeps values and shows a form-level error, and submit remains available (AC-16).
  - Provides a way to cancel and close the form.
- **Modify `App.tsx`:** replace the starter content with `<SessionsWorkspace />`. Leave the unused starter assets in place (no unrelated cleanup).
- **Modify `App.css` and `index.css`:** remove starter-only rules that no longer apply and add minimal layout styles for the new markup. Keep it small; visual polish is a non-goal. `index.css` may keep global resets.

State roles for the loading and error regions: loading uses `role="status"`, and the list error and the create error use `role="alert"`. This helps both users and test queries.

## 6. Tests

### Essential (AC-19), beside the behavior it protects
- **New `test/setup.ts`:** registers jest-dom, starts and closes the MSW server (`onUnhandledRequest: "error"`), and resets handlers and mock data after each test. Referenced from `vite.config.ts`.
- **New `features/sessions/SessionsWorkspace.test.tsx`:** renders the workspace against the MSW server and drives it as a user:
  1. **Filter flow (essential):** wait past the loading state, assert all seeded sessions appear with title, status and date. Choose one status and assert only that status remains. Choose `All` and assert everything returns.
  2. **Create flow (essential, same file):** open the form, enter a trimmed valid title and a future local date/time computed from the real clock (for example tomorrow), submit, and assert the form closes and the new title appears with `Planned`.

Assert user-visible outcomes only, not internal state or the call counts of the fetch layer.

### Additional risk-based opportunities (not required; do only if time remains, or leave to `test-generator`)
- Validation: title of 2 and of 81 characters, whitespace-only title, past date, a date within the 1-minute margin, empty date.
- List error then retry (override the handler with `server.use` to return 500 once), covering AC-4.
- Create failure keeps values and allows retry (AC-16).
- Double submit produces exactly one session (AC-13).
- Created session hidden under a non-matching filter (AC-7).

Notes: with `user-event`, typing into `datetime-local` accepts a local ISO string such as `2026-10-01T10:00`. Do not use fake timers together with MSW unless necessary.

## 9. Risks and Considerations

- **Toolchain compatibility:** Vitest, MSW or jsdom against Vite 8 / TypeScript 6 is unverified. Step A must confirm it before any code depends on it.
- **`erasableSyntaxOnly` and `verbatimModuleSyntax`:** no enums, parameter properties or namespaces. Use `import type` for types. `ApiError` as a class is fine, but avoid parameter-property shorthand.
- **Lint:** `react/only-export-components` is a warning. Keep component files exporting only components.
- **Mock code in production build:** it must be loaded only behind the dev check, so it stays out of `vite build`.
- **`StrictMode`:** the load effect runs twice in dev, so it needs abort or stale-result handling.
- **Time zone/clock:** validation uses the local clock. Tests must build dates relative to the real "now", never hard-coded past-sensitive literals.
- No feature flags or rollback plan needed for this scope.
